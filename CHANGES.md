# Изменения: LTE-генератор плазмы, предобработка и признаки по линиям

Цель: улучшить перенос моделей с синтетических спектров на реальные спектры прибора
ChemCam. До изменений модели, обученные на синтетике, почти не находили элементы
в реальных спектрах.

Как измерялось: 64 эталонных стандарта ChemCam (NASA PDS), 5 seed (7, 17, 29, 43, 71),
среднее по seed. Метрики:

- **Recall** — доля найденных элементов среди тех, что есть в образце (Na, Mg, Ca, Fe).
- **FPR** — доля ложных срабатываний на материалах, где оксида элемента ≤ 0,1 wt%.
- **ROC-AUC** — насколько хорошо оценки модели отделяют образцы с элементом
  (≥ 1 wt%) от образцов без него, независимо от порога. 1,0 — идеально, 0,5 — случайно.

Исходная точка — старый генератор на текущем коде (перезапуск `scripts/validate_chemcam.py`
после раздела 12): recall NNLS 0,009, Logistic 0,267, Random Forest 0,263. Все числа
в разделах 2–11 пересчитаны после изменения порога в разделе 12.

Полный отчёт: [docs/plasma_generator_v3.md](docs/plasma_generator_v3.md).
Все числа: [docs/plasma_replay_v3_summary.json](docs/plasma_replay_v3_summary.json).

## 1. Атомные данные NIST с энергиями уровней

- **Взял:** новый файл `scripts/prepare_plasma_reference_v3.py` и новый модуль
  `ml/src/spectralab_ml/data/plasma_reference.py`.
- **Изменил:** прежний справочник `data/reference/nist_neutral_350_800` хранил только
  длину волны и условную яркость линии нейтрального атома. Скачал 50 выгрузок
  NIST ASD (240–900 нм): линии с A_ki, E_i, E_k, g_i, g_k и списки уровней для
  25 частиц — H, He, Na, Mg, Ca, Fe, Si, Al, K, Ti, Mn, O, C, стадии I и II. Каждый
  файл закреплён SHA-256 в `data/reference/nist_plasma_v3/sources.json`, компактная
  таблица лежит в `data/reference/nist_plasma_v3/plasma_reference.json`.
- **Получил:** 11 267 переходов. Потенциалы ионизации совпадают с NIST
  (Na 5,139, Ca 6,113, Mg 7,646 эВ). Статсуммы считаются из уровней с отсечкой
  по понижению потенциала ионизации.
- **Это позволило:** считать яркость линий из физики плазмы, а не из условной шкалы.
  Без энергий уровней закон Больцмана применить невозможно.

## 2. Генератор спектров лазерной плазмы

- **Взял:** новый модуль `ml/src/spectralab_ml/simulation/plasma.py`. Старый
  `simulation/generator.py` не менялся.
- **Изменил:** вместо суммы шаблонов нейтральных линий генератор считает:
  - ионизацию по уравнению Саха с понижением потенциала по Дебаю;
  - заселённости уровней по Больцману;
  - линии атомов (I) и ионов (II) одновременно;
  - перенос излучения в слое I = B(T)·(1 − e^(−τ)), что даёт самопоглощение
    сильных линий;
  - сплошной фон плазмы (тормозное и рекомбинационное излучение);
  - две зоны, горячую и холодную, вместо одной температуры;
  - элементы породы (O, Si, Al, K, Ti, Mn) и атмосферный C как помехи;
  - разброс прибора: ширину аппаратной функции для каждого спектрометра, сдвиг шкалы,
    отклик, фон и шум.
- **Получил:** при тех же моделях и той же нормировке (вариант `plasma/maxabs`
  против `neutral-linear/maxabs`):

  | Модель | Recall до | Recall после |
  | --- | ---: | ---: |
  | NNLS | 0,009 | 0,898 |
  | Logistic | 0,267 | 0,881 |
  | Random Forest | 0,263 | 0,900 |

  ROC-AUC Mg у Random Forest выросла с 0,19 до 0,91, ROC-AUC Fe у Logistic — с 0,63 до 0,96.
- **Это позволило:** получить самый большой прирост из всех изменений. Модели впервые
  видят в обучении спектры, похожие на реальные: например, сильные ионные линии
  Ca II 393/397 нм и насыщенные резонансные линии.
- **Проверено тестами** (`ml/tests/test_plasma_generator.py`): излучение слабой линии
  совпадает с формулой Больцмана с точностью 0,5%, сильная линия насыщается,
  ионизация совпадает с формулой Саха.

## 3. Вычитание фона и нормировка по спектрометрам

- **Взял:** новый модуль `ml/src/spectralab_ml/preprocessing/robust.py`.
- **Изменил:** раньше весь спектр делился на один максимум. Теперь в каждой полосе
  спектрометра отдельно вычитается плавный фон (метод ALS), затем полоса делится
  на свою суммарную интенсивность. Разрыв между спектрометрами не соединяется.
- **Получил:**

  | Сравнение | Recall до | Recall после |
  | --- | ---: | ---: |
  | Logistic, старый генератор | 0,267 | 0,586 |
  | Random Forest, новый генератор | 0,900 | 0,934 |
  | NNLS, новый генератор | 0,898 | 0,911 |

  ROC-AUC Random Forest на новом генераторе: Mg 0,91 → 1,00, Fe 0,77 → 0,96.
- **Это позволило:** убрать различия в фоне и в чувствительности спектрометров между
  синтетикой и прибором. Без нового генератора эффект небольшой.

## 4. Признаки по окнам спектральных линий

- **Взял:** новый модуль `ml/src/spectralab_ml/models/line_features.py`.
- **Изменил:** вместо тысяч пикселей модель получает высоту пика каждой
  диагностической линии над локальным фоном. Это 10 линий на каждый определяемый
  элемент и по 5 на элементы-помехи. Положения линий взяты из синтетических
  спектров, а не из реальных. Модели — логистическая регрессия со стандартизацией
  и градиентный бустинг.
- **Получил** (вариант `plasma/lines` против `plasma/robust`, Logistic):

  | Метрика | До | После |
  | --- | ---: | ---: |
  | Mg: recall / FPR | 0,94 / 0,66 | **0,98 / 0,01** |
  | ROC-AUC Fe | 0,46 | 1,00 |
  | ROC-AUC Na / Mg / Ca / Fe | 0,97 / 0,68 / 1,00 / 0,46 | 1,00 / 1,00 / 1,00 / 1,00 |
  | Brier на реальных метках | 0,212 | 0,038 |
  | Recall (все элементы) | 0,928 | 0,905 |

- **Это позволило:** модели почти идеально отделяют образцы с элементом от образцов
  без него и почти не путают Mg. Общий recall немного ниже, зато резко меньше
  ложных срабатываний.

## 5. Калибровка вероятностей (temperature scaling)

- **Взял:** файл `ml/src/spectralab_ml/models/calibration.py` (добавлены
  `score_logits`, `fit_temperatures`, `TemperatureScaledEstimator`; прежний код
  не менялся).
- **Изменил:** для каждого класса подбирается одна «температура», делящая
  логит модели. Подбор идёт на половине синтетической валидации, пороги — на
  другой половине.
- **Получил** (ECE на синтетическом тесте, меньше — лучше):

  | Модель | До | После |
  | --- | ---: | ---: |
  | Random Forest, `plasma/robust` | 0,076 | 0,034 |
  | Gradient boosting, `plasma/lines` | 0,158 | 0,049 |
  | Logistic, `plasma/lines` | 0,052 | 0,030 |
  | Logistic, `plasma/robust` | 0,109 | 0,081 |

  Brier на реальных метках: Random Forest 0,089 → 0,063, Logistic (`robust`)
  0,212 → 0,161; у двух других без изменений.
- **Это позволило:** сделать выход моделей ближе к настоящей вероятности. Решения
  «есть / нет» почти не меняются: калибровка монотонна.

## 6. Оценка ложных срабатываний и ROC-AUC

- **Взял:** новый модуль `ml/src/spectralab_ml/evaluation/plasma_validation.py`.
- **Изменил:** прежняя проверка считала только recall, потому что подтверждённых
  отрицательных образцов нет. Добавил метки по опубликованному составу:
  ≥ 1 wt% — «есть», (0; 0,1] wt% — «нет», остальное — неизвестно. Это то же правило,
  что в адаптации ChemCam. По этим меткам считаются FPR и ROC-AUC.
- **Получил:** видно, что высокий recall бывает ложным. NNLS на новом генераторе
  отмечает Ca и Fe во всех образцах: recall 1,0, но и FPR 1,0. Число материалов
  «без элемента»: Na 14, Mg 7, Ca 2, Fe 3.
- **Это позволило:** сравнивать модели честно, а не только по recall.

## 10. Причина падения метрик v1

- **Взял:** `ml/src/spectralab_ml/models/estimators.py`, функцию `select_thresholds`.
  Сравнил коммит прогона v1 (`d81ee98`) с текущим.
- **Нашёл:** в ML v4 подбор порога по F1 перевели с сетки из 51 точки на перебор
  всех значений оценок. Когда классы на валидации разделимы, старый код ставил порог
  около нижнего края промежутка между отрицательными и положительными, а новый —
  ровно на минимальную оценку положительного примера, то есть на верхний край.
  На реальных спектрах оценки ниже, чем на синтетике, и высокий порог пропускает
  почти всё.
- **Проверил:** подставил в текущий код старый перебор без других изменений и
  получил опубликованные числа точно: NNLS 0,0374, Logistic 0,4549, RF 0,6827.
  С новым перебором: 0,0002 / 0,0574 / 0,2293. Коммит `d81ee98` в отдельной копии
  тоже даёт 0,0374 / 0,4549 / 0,6827.
- **Это позволило:** убедиться, что код воспроизводим, а падение вызвано одной
  функцией, не данными. Исправление — в разделе 12.

## 11. Порог на реальных спектрах прибора

- **Взял:** `scripts/validate_chemcam_plasma.py` (добавлены `load_adaptation`,
  `real_threshold_entry`, `aggregate_real`, параметр `--protocol`) и новый протокол
  `data/reference/chemcam_plasma_real_thresholds_protocol.json`. Подбор порога —
  существующая функция проекта `select_operational_thresholds`.
- **Изменил:** модели обучаются только на синтетике, как раньше. Порог для Na, Mg, Ca
  и Fe теперь подбирается не на синтетике, а на 127 лабораторных спектрах ChemCam
  calib_2015: максимум recall при FPR ≤ 5%. Проверка — на 71 образце calib_2021
  (отрицательных: Na 30, Mg 21, Ca 10, Fe 17) и на 64 preflight.
- **Получил** (признаки по линиям + логистическая регрессия, `plasma/lines`,
  среднее по 5 seed):

  calib_2021, 71 образец, recall / FPR:

  | Элемент | Порог с синтетики | Порог с calib_2015 |
  | --- | ---: | ---: |
  | Na | 0,76 / 0,33 | 0,70 / **0,00** |
  | Mg | 0,88 / 0,12 | 0,91 / 0,15 |
  | Ca | 0,83 / 0,24 | 0,73 / **0,00** |
  | Fe | 0,75 / 0,32 | 0,64 / **0,02** |

  Preflight, 64 образца, recall / FPR:

  | Элемент | Порог с синтетики | Порог с calib_2015 |
  | --- | ---: | ---: |
  | Na | 1,00 / 0,58 | 0,97 / **0,03** |
  | Mg | 0,98 / 0,01 | 0,98 / 0,04 |
  | Ca | 1,00 / 1,00 | 0,99 / **0,00** |
  | Fe | 1,00 / 0,60 | 1,00 / 0,47 (всего 3 отрицательных) |

  Recall по всем известным положительным меткам preflight: 0,905 → 0,836.

  Для сравнения, на тех же 71 образцах calib_2021 и с тем же правилом меток прежняя
  модель проекта из `docs/instrument_adaptation.md`, обученная на реальных спектрах,
  давала recall / FPR: Na 0,43 / 0, Mg 0 / 0, Ca 0,53 / 0, Fe 0,65 / 0,47.
- **Это позволило:** снизить ложные срабатывания Na, Ca и Fe до 0–3% при recall
  0,64–0,72 на независимом от подбора наборе. У Mg FPR 0,15 — выше цели в 5%:
  порог Mg с calib_2015 переносится хуже.
- **Ограничения:** calib_2021 уже раскрывался в адаптации проекта, поэтому это тоже
  повторное использование, а не новая финальная проверка. С temperature scaling
  реальные пороги работают хуже (например, Ca 0,30 / 0,00): калибровка на синтетике
  сжимает оценки реальных спектров к 0 или 1. Запуск
  `plasma-replay-20261022T200445-a45f2850`, сводка —
  `docs/plasma_real_thresholds_v4_summary.json`. Команда:
  `scripts/uv.sh run --frozen --all-packages --no-sync python scripts/validate_chemcam_plasma.py --protocol data/reference/chemcam_plasma_real_thresholds_protocol.json`
  (нужны `make external-validation-download` и `python scripts/prepare_instrument_data.py`,
  ~1 ГБ с NASA PDS).

## 12. Порог по середине промежутка в `select_thresholds`

- **Взял:** `ml/src/spectralab_ml/models/estimators.py`, функцию `select_thresholds`,
  и `ml/tests/test_core_numeric_contracts.py`.
- **Изменил:** правило выбора лучшей границы по F1 осталось прежним. Раньше порог
  ставился ровно на наименьшую принятую оценку (верхний край промежутка между
  классами). Теперь он стоит посередине между наименьшей принятой и наибольшей
  отвергнутой оценкой. Решения на валидации от этого не меняются. Если отвергнутых
  оценок нет, порог остаётся на наименьшей оценке. `schema_version` в метаданных
  порога: 2 → 3. Тесты обновлены, добавлен тест на середину промежутка.
- **Получил:** recall на 64 preflight, старый генератор (`scripts/validate_chemcam.py`):

  | Модель | Порог на краю | Порог посередине | Опубликовано в v1 |
  | --- | ---: | ---: | ---: |
  | NNLS | 0,0002 | 0,009 | 0,037 |
  | Logistic | 0,057 | 0,267 | 0,455 |
  | Random Forest | 0,229 | 0,263 | 0,683 |

  Synthetic micro-F1 старого генератора: NNLS 0,966 → 0,999, Logistic 0,965 → 0,998,
  RF 0,958 → 0,981. На новом генераторе recall почти не изменился
  (признаки по линиям: 0,899 → 0,905), ROC-AUC не меняется вовсе. Пороги, подобранные
  на calib_2015 (раздел 11), от `select_thresholds` не зависят, поэтому их метрики
  совпали до знака.
- **Это позволило:** вернуть порогу запас в обе стороны и частично восстановить
  перенос старых моделей. Опубликованные числа v1 полностью не возвращаются: старая
  сетка из 51 точки ставила порог ещё ниже середины. Побочный эффект: на preflight
  FPR Ca для признаков по линиям с синтетическим порогом вырос с 0,47 до 1,00 (всего
  2 отрицательных образца); с порогом из calib_2015 он остаётся 0,00.
- **Важно:** функция общая для всего проекта. Модели, которые обучаются заново через
  `training.py` (demo, эксперименты, API), получат новые пороги. Уже сохранённые
  артефакты и опубликованные отчёты прежних экспериментов не пересчитывались.

## Что осталось

1. **Пороги.** Решено подбором на calib_2015 (раздел 11), кроме Mg (FPR 0,15 на calib_2021)
   и Fe на preflight (3 отрицательных образца — оценка ненадёжна).
2. **Ограничение проверки.** Эти 64 стандарта уже использовались в проверке v1, поэтому
   результат — повторная проверка, а не независимая финальная оценка.
3. **Воспроизводимость v1.** Причина найдена (раздел 10), порог исправлен (раздел 12);
   опубликованные числа v1 полностью не возвращаются из-за другой сетки порогов.
4. **Прежние отчёты проекта** (`docs/research_results.md`, `docs/expanded_benchmark.md` и др.)
   получены со старым правилом порога и не пересчитывались.
