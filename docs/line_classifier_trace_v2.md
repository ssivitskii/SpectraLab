# Слабые компоненты: line-logistic-robust

В «Анализе» доступен дополнительный экспериментальный вариант
`line-logistic-robust`. Прежний `line-logistic` сохранён; модель по умолчанию
не менялась. Все результаты — synthetic development на `demo_fixture`,
не независимый final и не проверка реального прибора.

## Что изменено

Предварительная проверка seed 42 показала: при относительном весе второго
компонента 0.10 прежняя модель нашла его лишь в 1 из 30 ordered pairs.
Это диагностический результат, не итоговая метрика нового протокола.
Ранее обучающие веса выбирались из узкого интервала 0.35–1.2.

Новый профиль генерации `line_robust_v1` задаёт веса log-uniform 0.02–1
с нормировкой максимального веса до 1. Состав и веса фиксированы для base group;
все её shots остаются в одном split. Для вариаций используются SNR 10/20/30/40 dB,
FWHM 0.2/0.5/1.0 nm, shift uniform ±0.5 nm, фон 0/0.5/2 clean peak
и линейный наклон с end-to-end изменением до ±0.5 clean peak.
Точные параметры каждого спектра сохраняются в стандартном manifest.

Одного расширения генерации оказалось недостаточно: exploratory вариант
чаще давал ложные срабатывания. В итоговом варианте каждый элемент использует
только собственные справочные окна: до 36 признаков, а не признаки других
элементов. Геометрия окон, arcsinh, train-only scaling и C=1 не изменены.
Группы признаков сериализуются и проверяются вместе с manifest; старые
line-logistic артефакты совместимы. Выход — decision margin, не вероятность.

## Протокол

Пять seed: 7, 17, 29, 43, 71. Для каждого варианта — 144 base groups ×2 shots:
86 train, 29 validation, 29 test. IDs и размеры splits совпадают, но генерация
различается. Пороги подбираются отдельно на validation соответствующего профиля.
Сравнение — изменение training distribution **и** ограничение classifier scope;
это не чистая ablation одного фактора. Метрики собственных test splits нельзя
напрямую сравнивать: они описывают разные распределения.

Для общего сравнения обе модели получают одни и те же controlled arrays:
30 ordered element pairs ×2 noise realizations ×5 seed, **300 спектров на
condition**, 10 conditions. SNR=20 dB, FWHM=0.5 nm; дополнительные факторы
указаны ниже. Контролируемый фон равен двум clean peaks, его фиксированный
наклон даёт end-to-end изменение 0.4 от уровня фона.

Evaluation IDs и генераторные seeds отделены от train/validation/test.
При ratio=0 целевой элемент действительно удаляется из генератора, а не
генерируется с недопустимым нулевым весом. Оставшийся элемент служит матрицей.
Это известные отрицательные контроли, не неизвестные элементы.

Составы и noise seeds повторяются между conditions; это не 300 новых физических
материалов. SD в JSON — разброс по seed, не физический доверительный интервал.
Проверка выбрана после диагностики v1, поэтому называется development.
Controlled результаты не использовались для подбора итоговых порогов.

## Результаты

Средние по пяти seed; полнота относится именно ко второму, слабому компоненту.
Вес — относительный параметр генератора, **не концентрация**.

| Условие | micro-F1 v1 | micro-F1 robust | Полнота слабого v1 → robust |
| --- | --- | --- | --- |
| Веса 1:1 | 1.000 | 1.000 | 100% → 100% |
| Веса 1:0.10 | 0.724 | 1.000 | 13.7% → 100% |
| Веса 1:0.03 | 0.667 | 0.934 | 0% → 75.3% |
| Веса 1:0.01 | 0.667 | 0.706 | 0% → 9.3% |
| 1:0.10, фон ×2 | 0.667 | 0.955 | 0% → 83.0% |
| 1:0.03, фон ×2 | 0.667 | 0.693 | 0% → 6.3% |
| 1:0.10, shift 0.50 nm | 0.671 | 0.992 | 1.0% → 99.0% |
| 1:1, shift 0.75 nm | 1.000 | 0.958 | 100% → 100% |
| Компонент отсутствует | 1.000 | 1.000 | не применимо |
| Компонент отсутствует, фон ×2 | 1.000 | 1.000 | не применимо |

Для весов 0.10 и 0.03 без фона прирост F1 положителен на каждом seed.
На двух absence conditions (600 наблюдений суммарно) обе модели не дали
ложных срабатываний; это наблюдение на ограниченном наборе, не гарантия нулевого
риска. При shift 0.50 nm robust дал 0.58% ложноположительных решений среди
отрицательных element decisions; при shift 0.75 nm — **4.42%**, у v1 — 0%.
Для последнего condition exact match снизился с 1.000 до 0.823.

Таким образом, вариант полезен для слабых компонентов при малом drift,
но **не является безусловной заменой v1**. При крупном drift нужно сравнивать
оба результата; предупреждение выводится в API/UI. Вес 0.01 и слабый компонент
на большом фоне остаются сложными. Реальный предел обнаружения, неизвестные
элементы, plasma matrix effects и концентрации не валидированы.

## Воспроизведение

```bash
make line-model-robust
make line-model-trace-benchmark
# Сохранить полный новый отчёт в выбранный файл:
scripts/uv.sh run --frozen --all-packages --no-sync python scripts/benchmark_line_trace.py \
  --summary reports/verification/line_trace_reproduction.json
```

Артефакт — `artifacts/models/line-logistic-robust`, базовый seed 42.
Обновите страницу «Анализ», выберите `line-logistic-robust`.
Прежние модели не перезаписываются. Benchmark создаёт отдельную новую папку
и не заменяет существующий run. Он обучает модели заново и сохраняет их,
manifest, пороги, split IDs, source hashes и поэлементные метрики.

Исходный run: `reports/experiments/line-trace-v2-20261023T190122/summary.json`.
Tracked [компактный JSON](line_classifier_trace_v2_summary.json) содержит
агрегаты, per-seed значения, evaluation hashes, training/model hashes и SHA-256
полного локального отчёта. Исходные runs и checkpoints — локальные производные.

Проверки реализации: 671 Python passed, 4 skipped; 54 UI tests и 10 browser E2E
passed. Ruff, ESLint, TypeScript и production build прошли. Тесты проверяют
group isolation, воспроизводимость, explicit absence, feature locality,
artifact/registry roundtrip и предупреждение о границах применимости.
