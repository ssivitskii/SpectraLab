На текущем коде прошли 33 frontend-теста, lint и production-сборка;
desktop/mobile-проверка и сквозной CSV-сценарий описаны в [photon.md](photon.md).
Ниже сохранены исторические проверки предыдущих итераций.

## Контракты и состояния

- API-клиент сохраняет `error.code`, HTTP-статус и детали валидации. Обрабатывает
  обрыв соединения, timeout, отмену, HTML-ответ шлюза и повтор после ошибки.
- Запросы чтения и prediction получают `AbortSignal`. Смена spectrum/model
  отключает прежний запрос, а его поздний ответ не показывается для нового выбора.
  У выбранных моделей отдельные результаты, loading/error и повтор запроса.
- Размер и заголовки CSV, количество точек и конечность чисел проверяются до POST.
  Среда, диапазон и лимиты поступают из `/capabilities`; сервер остаётся последней
  инстанцией проверки. Ошибки загрузки связаны с полем через `aria-describedby`.
- Модели показывают версию, источник, `score_kind` и причину недоступности.
  Некалиброванные оценки остаются числами своей шкалы. Сравнивается состав,
  оценки разных моделей не усредняются. Пустое обнаружение не означает open-set.
- История работает по сохранённым ID. Ссылки `?spectrum=` и `?run=` переживают
  обновление страницы. Metadata пользователя сохраняются отдельно от вычисленных
  свойств; SNR загруженного измерения неизвестен.
- Экспорт использует сохранённые записи BE05 и manifest. Пресет хранится локально
  с собственной версией схемы, профилем сервиса, источником, параметрами физики и
  seed; несовместимый профиль не восстанавливается молча.
- Каталог экспериментов использует cursor API с фильтрами; изменение фильтра
  открывает первую страницу. Средние, SD (`ddof=1`) и `count` берутся из API без
  пересчёта научных метрик. `null` остаётся отсутствующим значением. Видны состав
  серии и причины failed/incomplete. Разные протоколы, источники/checksum и типы
  отчёта явно исключаются из сравнения.
- Задание восстанавливается по `?job=`. Серверные статусы и completed/total
  показываются напрямую. Повтор запроса использует тот же idempotency key, включая
  перезагрузку страницы; осознанный повтор failed/cancelled создаёт новый запрос.

## Автоматические проверки

`make test`: 33 frontend unit/component теста в шести файлах. Покрыты сетевые
ошибки, HTML 502, timeout/cancellation, поздние результаты, независимый отказ одной
модели, CSV без POST, истинные метки отдельно от prediction, пустой список,
неполные серии, `null`, single/mixture, несовместимые протоколы и смена cursor-фильтра.

`make e2e`: шесть Playwright тестов на реальном FastAPI в изолированном временном
каталоге. `scripts/e2e_server.py` создаёт небольшой обученный baseline, оставляет
другие обучаемые модели недоступными, создаёт явно помеченную запись каталога и
запускает отдельный worker в режиме `--batches-only` и удаляет временные данные
при завершении. Пользовательские данные не затрагиваются.

Браузерные сценарии:

1. generator → analysis → две модели → экспорт JSON с проверкой source/model ID,
   версии, предупреждений и manifest; metadata/history и пресет после reload;
   проверка, что true labels отсутствуют в запросе `/predict`.
2. CSV upload, клиентский отказ без POST, отсутствие модели, реальная ошибка
   неизвестного spectrum ID и возможность повтора.
3. Каталог и пустой фильтр, восстановление run/job по ссылке, идемпотентность
   создания задания до/после reload и отмена.
4. Benchmark 100 000 точек и 1 000 справочных линий.
5. Выбор настоящей папки с вложенным CSV, ошибочным CSV и README (пропускается), две модели,
   независимые результаты и отказ без отправки ошибочных CSV-байтов; reload,
   повтор незавершённых с сохранением успешных prediction ID и JSON-отчёт с
   pinned model version, reference checksum, input checksum и origin проверки.
6. Восстановление серверного draft: изменённое содержимое того же имени отклоняется;
   повторный выбор файлов после reload отправляет только недостающий CSV.

В первом сценарии также проверяются реальная отрисовка Plotly, клавиатурное
выделение строки reference/observed/delta, сохранение zoom после смены слоя,
клавиатурный ввод диапазона и отсутствие горизонтального переполнения при 820 px.
Скриншоты анализа и пакетной очереди в 1440/820 px проверены визуально. Это эмуляция размера viewport на desktop,
а не тест физического мобильного устройства или скринридера.

При сбое Playwright сохраняет screenshot, video, trace и HTML-отчёт. CI выгружает
артефакты. Локальные результаты находятся в `frontend/test-results/` и
`frontend/playwright-report/`; эти каталоги исключены из Git. `lint`, TypeScript
и production build проходят. Plotly загружается отдельным ленивым чанком; Vite
сообщает о его размере около 1 MB (361 kB gzip).

## Папка CSV и восстановление очереди

Маршрут `/batch` использует браузерный `webkitdirectory` с резервным выбором
нескольких файлов. При выборе папки включаются только `.csv` без учёта регистра
расширения, а число остальных файлов показывается отдельно. Папка без CSV не
создаёт очередь. Относительный путь служит подписью; серверный путь к папке
не запрашивается. Лимиты числа файлов, числа моделей, размера CSV и общего
объёма принятых файлов берутся из `/capabilities`. Суммарный объём локально
валидных CSV проверяется перед созданием; ошибочные файлы не учитываются в нём.

До передачи байтов сервер сохраняет весь ожидаемый состав очереди: относительные
пути, размеры и SHA-256. Ошибочные файлы передаются отдельным JSON-описанием отказа,
а oversized-файлы не читаются целиком для hashing и получают `sha256: null`.
Сервер независимо валидирует загруженные CSV. Ошибка одного файла не прекращает
другие загрузки; сетевой сбой оставляет файл ожидающим и позволяет повторить
только недостающие записи. Кнопка паузы останавливает intake после текущего
запроса. Анализ стартует только после учёта всех заявленных файлов.

`?batch=` восстанавливает состояние с сервера, а неизвестный исход создания
можно повторить из `sessionStorage` с прежним idempotency key. После закрытия
страницы доступ браузера к незагруженным файлам теряется: нужно повторно выбрать
ту же папку. Совпадение пути, размера и SHA-256 обязательно; изменённые исходные
данные требуют новой очереди. Уже принятые файлы не отправляются повторно.

Очередь и отдельные результаты показывают серверные статусы. `completed`
в прогрессе включает успешные и ошибочные результаты; `failed` показан отдельно.
Worker выполняется независимо от страницы. Повтор partial/failed/cancelled
оставляет завершённые prediction ID, версии моделей и источник зафиксированными.
UI показывает client/server origin отказа, input checksum, spectrum ID, версию
модели, источник, score kind, calibration flag, оценки, пороги и предупреждения.
Шкалы разных моделей не усредняются. Экспорт JSON/CSV/ZIP использует серверный
сводный отчёт и его manifest.

Десять новых unit/component тестов проверяют смешанный набор valid/invalid CSV,
восстановление intake, изменение checksum, потерянный ответ создания после remount,
независимый отказ модели и экспорт, oversized-файл без чтения байтов, дубли имён
и лимит количества, продолжение после сетевого сбоя и адресный повтор,
папку с `.CSV` и README, папку без CSV.
Браузерные тесты используют реальные API и отдельный процесс worker, не заглушки.

## Измерение плотного графика

Среда: Headless Chromium **141.0.7390.37**, macOS arm64, **Apple M1, 8 GB RAM,
8 логических процессоров**, viewport **1440 × 1000**. Измерение 2026-10-13.
После прогрева выполнены три чередующихся прогона каждого режима.
`performance.now()` охватывает подготовку данных, `Plotly.newPlot` и два
`requestAnimationFrame`. Загрузка модуля, сеть и холодный запуск браузера сюда
не входят.

| Режим | Точки сигнала | Справочные линии | Прогоны, ms | Медиана, ms |
| --- | ---: | --- | --- | ---: |
| Исходный | 100 000 | 1 000 отдельных shapes | 217,3; 148,5; 151,3 | 151,3 |
| Оптимизированный | 3 924 | один trace с разделителями | 48,5; 47,0; 81,3 | 48,5 |

В этом прогоне время уменьшилось примерно на **68% (3,12 раза)**. Это измерение
данного браузера и устройства, не гарантированная скорость для всех окружений.

Алгоритм сохраняет минимумы/максимумы каждого интервала и исходные x-координаты,
включая крайние точки, при лимите до 4 000 отображаемых точек. Единичные узкие пики
сохраняются. Исходные массивы не изменяются: prediction и CSV/JSON продолжают
использовать все точки. Таблица линий разбита на страницы по 50 строк, фильтруется
по элементу и связана с выделением графика. `uirevision` привязан к spectrum ID;
очистка Plotly выполняется при размонтировании, а не при переключении слоя.

Воспроизведение только benchmark:

```bash
PLAYWRIGHT_BROWSERS_PATH="$PWD/.cache/ms-playwright" \
  scripts/npm.sh --prefix frontend exec -- playwright test \
  --config=frontend/playwright.config.ts benchmark.spec.ts
```

Полный JSON с отдельными замерами создаётся в соответствующем каталоге
`frontend/test-results/`. Сохранённая копия текущего локального прогона:
`artifacts/frontend-validation/dense-spectrum-benchmark.json`.
