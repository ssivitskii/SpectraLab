# Независимая финальная проверка Fe/Mg: аудит выполнимости v6

Дата проверки: 2026-10-19. Зафиксированные веса доступны, однако новый независимый
финальный набор с допустимыми blank-контролями ещё не установлен. Метрики final
остаются `null`. Этот аудит читает прежние метаданные, существующий численный
профиль модели и три публичные страницы с описанием Aalto. Новые финальные
интенсивности не скачивались, не открывались и не передавались модели.

Машиночитаемые результаты, хеши источников и нерешённые вопросы:
[final_search_v6_feasibility.json](../data/reference/final_search_v6_feasibility.json).
Исторические протоколы и модели не изменены.

В этой версии изменён только классификатор Ca. Fe/Mg, их признаки, калибровка и
пороги остаются из вложенного v3. Для Mg используются 32 линии в пределах
245.0332–883.7508 nm, для Fe — 32 линии 249.401546–649.67746 nm. Окна линии имеют
полуширину 0.2 nm, боковые окна — от 0.5 до 1 nm. При финальной оценке binder
возвращает вероятности для бинарного сравнения с фиксированными порогами: отказ
`unknown` не скрывает ошибки из знаменателя.

Применение к данным на air-оси допустимо только через документированное преобразование
с привязкой исходного и преобразованного файлов по SHA-256. Атмосфера измерения сама
по себе не определяет air/vacuum-конвенцию оси. Нельзя достроить отсутствующие полосы
нулями, заменить приборное имя или обрезать нормировку, сохранив утверждение, что
проверяется тот же контракт.

## Что уже зафиксировано, а что ещё предстоит определить

[final_campaign_v6_manifest.json](../data/reference/final_campaign_v6_manifest.json)
содержит проверенную привязку неизменного численного профиля и девяти файлов
реализации. Проверка отражена в
[final_profile_v6_binding.json](final_profile_v6_binding.json). `samples`,
`data_source`, `support_policy` остаются пустыми,
`selection_frozen_before_predictions=false`. Metadata-only preflight блокируется
15 причинами отсутствия источника, допустимых samples и support policy. Это заготовка,
а не завершённый final-freeze. Старый v4-manifest с пустым profile сохранён как история.
Наблюдавшиеся v6 manifest/binding/preflight сохранены отдельными metadata-снимками;
его preflight предшествует окончательной перепривязке нового seen-registry. Поэтому
хеш наблюдавшегося registry и окончательный v6 SHA отдельно записаны в JSON аудита.
Веса фиксированы; финальная выборка и её численное требование к
точности ещё не выбраны. Поэтому утверждения «протокол уже требует 30/59/73
материала» были бы неверны.

Текущая schema 3 требует для каждого Fe и Mg отдельную поддержку трёх групп:
positive, ordinary negative и blank. Для каждой группы заранее задаются минимумы
physical, family, session и independent clusters — положительные целые числа.
Для интервала нужно как минимум два независимых связанных компонента и выполнение
выбранного предела ширины. Связи по physical/family/session/checksum транзитивны:
много выстрелов одного образца, либо много материалов одной сессии, не гарантируют
много независимых компонентов.

Точечные метрики имеют равный вес физических материалов после усреднения повторов.
Wilson-интервал относится к другому, консервативному estimand — наличию хотя бы
одной ошибки в связанном компоненте. Это не биномиальный интервал для точечной
материальной FPR. Остаточная зависимость между компонентами остаётся предположением.

Иллюстрации при 95% confidence, не новые требования:

| Допустимая худшая полуширина Wilson | Минимум независимых компонентов в каждой группе |
| --- | ---: |
| 0.30 | 7 |
| 0.20 | 21 |
| 0.10 | 93 |
| 0.05 | 381 |

Использована формула `z / (2 sqrt(n + z²))`. При нуле ошибок верхняя граница
двустороннего 95% Wilson становится ≤5% начиная с 73 независимых компонентов.
Это отдельный пример для наблюдаемого нулевого числа ошибок, а не гарантия результата
и не заранее принятый размер нашего final. Выбор precision должен следовать цели
проверки до просмотра результатов. Один допустимый blank можно честно описать как
ограниченную проверку конкретного контроля, но он не удовлетворяет текущей полной
кампании с интервалами для всех шести групп.

## Реальные ограничения и чрезмерно сильные предположения

| Вопрос | Что действительно требуется |
| --- | --- |
| Обязательно ли формальное CoA? | Код требует `certified=true`, независимую верхнюю границу, метод и прослеживаемую связь с физическим материалом. Поля «ISO-аккредитация» или обязательного фирменного CoA нет. Публикуемый независимый assay с обоснованной границей и описанным контролем может быть научным доказательством; соответствие его смысла полю `certified` нужно явно рецензировать. |
| Достаточно ли низкого assay point estimate? | Положительное значение `0 < oxide wt% ≤ 0.1` может дать обычную operational-negative метку. Оно само по себе не задаёт верхнюю границу blank. Ноль, пропуск и неизвестный LoD остаются unknown. |
| Нужен ли один материал с обоими элементами? | Нет: schema 3 разрешает разные документированные blank-семейства для Fe и Mg. Для каждого требуется соответствующая независимая граница ≤0.1 oxide wt%. |
| Любой чистый металл — blank? | Нет: нужны сведения о партии/материале, примесях и подготовке matrix/method control. Название «pure», номинальная формула или рекламная чистота без привязки недостаточны. Dark/no-laser — отдельный контроль прибора, не matrix/method blank. |
| Запрещён ли другой прибор научно? | Текущий binder действительно допускает только `chemcam-lanl-testbed`. Однако отдельная OOD-оценка неизменных весов на другом документированном приборе научно возможна. Для неё нужен новый заранее рассмотренный контракт/адаптер и явно иной вывод о применимости. Переименовать чужой прибор недопустимо. Переобучение не обязательно для OOD-теста и уже изменило бы проверяемую модель. |
| Можно ли считать новый URL независимым набором? | Нет: нужно исключить повторный физический материал, исходную партию/семейство, сессию, assay и перепакованные байты. Новое имя файла или другая дата публикации не устанавливают независимость. |

В этом аудите ни одно требование не ослаблено и ни один `certified=true` не добавлен
к данным кандидата. Если опубликованное доказательство не соответствует текущему
смыслу поля, требуется явное версионированное уточнение до numerical freeze, а не
скрытая подмена отрицательной метки. Более узкий тест только blank-FPR также был бы
другим заранее сформулированным протоколом; текущий полный final нельзя объявить
завершённым его результатами.

## Реестр ранее просмотренных данных

Создан отдельный
[final_seen_registry_v6.json](../data/reference/final_seen_registry_v6.json).
Исторический `final_search_v3_admission.json` сохранён. Новый реестр не объявляет
проверку независимости полной: `review_status=incomplete`,
`complete_independence_review=false`.

Старый реестр уже покрывал все 202 development-спектра: 199 physical, 191 family,
53 session, 202 measurement и 202 input hash. Он также содержал после нормализации
все 64 физических имени прежнего preflight и хеш его общей матрицы с 255 спектральными
повторами. Это перекрывающиеся наборы, их числа нельзя складывать как независимые
материалы. У общей старой матрицы нет 255 отдельных registry measurement IDs;
перепакованные строки нужно отсеивать через материалы, сессию и происхождение.

В v6 добавлены:

- 41 отсутствовавший assay ID из 64 старых preflight-строк. ID включает SHA
  таблицы состава и номер строки, поэтому перепубликация спектра не стирает источник
  прежней химической метки.
- Документированный прежний Aalto Cu export: CSV SHA
  `6d1007726b733b589563cb95bbede4c4dce1ef72d02c0d21e58899d75c646e42`, а также
  хеш старого plot-файла. Его material/family/aliases ограничены источником Aalto;
  это не запрет любого нового медного образца. Партия и сессия этого Cu не восстановлены.
- Точные хеши двух ранее скачанных Fe–Co HDF5. Старый аудит подтверждает просмотр
  метаданных/оси, но не позволяет утверждать, что интенсивности использовались.
  Они явно помещены в quarantine. Одиннадцать возможных sample IDs оставлены в
  списке для проверки, не выданы за достоверно model-seen материалы.
- 1601 типизированное alias-ребро с хешированными источниками: точные поля Target,
  Spectrum Name, Sample Name и уже проверенные physical/family-группировки.
  Нечёткий поиск не используется. Неоднозначные названия не объединяются, если
  исходный план не подтверждает один и тот же physical ID для всех совпавших строк.

| Поле блокировки | Старый реестр | v6 |
| --- | ---: | ---: |
| Measurement IDs | 203 | 204 |
| Physical IDs | 247 | 248 |
| Family IDs | 207 | 249 |
| Session IDs | 54 | 54 |
| Input hashes | 206 | 210 |

Числа включают сохранённые консервативные исключения и не являются числом фактически
обучающих наблюдений. `CA9LVNP1`, `DIHUQ1`, `HWHL101`, `HWMK104`, `MCCSG1`, `PSNJ1`
сохранены как неоднозначные опубликованные aliases, не объединены автоматически.
Для SGR1 и M6-HAGGERTY остаётся вопрос индивидуальной истории просмотра: их химические
строки исключались из старой оценки, но общая матрица была прочитана. Отсутствие их
имён в списке не даёт оснований принять их как untouched final.

Компилятор
[prepare_final_seen_registry_v6.py](../scripts/prepare_final_seen_registry_v6.py)
читает только перечисленные метаданные и таблицу состава. Ранее сохранённые
спектральные CSV/HDF5 он не открывает. Хеши файлов берутся из хешированного прежнего
аудита; это provenance-цепочка, а не новая проверка содержимого интенсивностей.
Старые raw-метаданные, необходимые для воспроизведения, перечислены в `source_metadata`;
часть из них gitignored, поэтому одного свежего clone недостаточно.

Воспроизведение в новый, ещё не существующий файл:

```sh
scripts/uv.sh run --frozen --all-packages --no-sync python scripts/prepare_final_seen_registry_v6.py --output .cache/final_seen_registry_v6_rebuilt.json
scripts/uv.sh run --frozen --all-packages --no-sync pytest ml/tests/test_final_seen_registry_v6.py -q
```

Три теста на вымышленных данных проверяют сохранение истории без мутации,
транзитивные типизированные aliases, источник-ограниченный Cu и quarantine,
необъединение неоднозначных материалов, а также отказ при подмене таблицы состава
или неоднозначном old-preflight mapping. Ещё два теста проверяют фактическое
metadata-покрытие прежних 202 + 64, хеш Aalto Cu и транзитивные aliases, а также
детерминированную пересборку при наличии исторических metadata-снимков. Все пять
пройдены; новая спектральная нагрузка в них отсутствует.
Успешный structural preflight сам по себе не проверяет `review_status` и не закрывает
перечисленные вопросы независимости: перед перепривязкой кампании нужен обзор реестра.

## Повторная проверка Aalto: нового допустимого контроля не найдено

Официальная страница по-прежнему предоставляет CC0 для pure-elements, но ссылка на
полный raw dataset является `TODO`. Для остальных наборов условия проверяются отдельно;
например, REE-коллекция имеет отдельную незавершённую запись о лицензии.
[Источник: Aalto datasets](https://users.aalto.fi/~lainei1/pages/datasets/).

Аппаратное описание приводит конфигурацию 2023 года с двумя
AvaSpec-ULS-4096CL-EVO и номинальными диапазонами 200–400 / 350–950 nm. Это делает
полное покрытие технически возможным, но не доказывает диапазон конкретного экспорта,
его разрешение, происхождение партии или совместимость с ChemCam.
[Источник: LASOLIBS](https://users.aalto.fi/~lainei1/pages/LASOLIBS/).

Описание калибровки использует полиномиальное согласование с теоретическими линиями
и O/N воздуха. Явной air/vacuum-конвенции экспортированной оси там нет. Выводить
её из того, что O/N присутствуют в окружающем воздухе, нельзя.
[Источник: Aalto calibration](https://users.aalto.fi/~lainei1/pages/calibration/).

На этих трёх страницах не обнаружена новая прослеживаемая партия с независимыми
верхними границами Fe/Mg и описанной подготовкой blank. Это ограниченный отрицательный
результат проверки конкретных metadata-страниц, не доказательство отсутствия любых
иных документов. Новые individual element plots, ноутбуки со встроенными массивами
или численные спектры в этом повторном поиске не открывались. Снимки страниц и
SHA-256 сохранены в `data/raw/final_search_v6_feasibility/` и реестре аудита.

## Безопасный следующий этап

1. Рассмотреть v6-registry и установить source-qualified physical/lot/session связи
   для каждого нового кандидата. Непроверенная независимость остаётся блокером.
2. Найти независимые количественные верхние границы для Fe и Mg с единицами,
   неопределённостью/методом и привязкой к подготовленному физическому контролю.
   Формальный сертификат — один возможный источник, не единственный научный путь.
3. Выбрать существующий same-instrument final либо отдельно сформулированный OOD
   тест неизменных весов. Зафиксировать вывод, который такой тест действительно допускает.
4. До оценок объявить поддержку, precision и правила включения; подтвердить лицензию,
   ось, все полосы, разрешение и отсутствие перекрытия, затем зафиксировать файлы,
   runtime и receipt-хранилище.
5. Выполнить ровно один оценочный проход и сохранить все результаты. Пока эти условия
   не выполнены, не заполнять final-FPR, recall или blank score development-метриками.
