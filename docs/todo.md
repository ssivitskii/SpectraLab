## ML и исследования

Точки входа: [конфигурация](../ml/src/spectralab_ml/config.py),
[эксперименты](../ml/src/spectralab_ml/experiments.py),
[генератор](../ml/src/spectralab_ml/simulation/generator.py),
[протокол](experiment_protocol.md). Demo использует `demo_fixture`; CLI и API
поддерживают явно выбранный проверенный reference cache. Серии сохраняют все seed
и общий отчёт.

- [x] **ML01 · P0 · Строгая конфигурация проекта и экспериментов.** Ввести
  типизированные схемы YAML, запрет неизвестных полей и явную версию конфигурации.
  Проверять диапазон, сетку, seed, размеры выборок, модели и совместимость факторов
  до создания каталога запуска. **Готово:** все существующие конфиги проходят
  проверку; опечатка, недопустимый тип и несовместимые параметры завершаются
  содержательной ошибкой без частично созданного запуска. **Зависимости:** нет.

- [x] **ML02 · P0 · Подключение трассируемого справочника.** Добавить выбор локального
  reference cache в обучение и эксперименты; подготовить сохранённые выгрузки для
  поддерживаемых элементов с metadata и checksum. Сохранять выбранный источник и
  его версию в dataset/model/run. `make demo` оставить воспроизводимым на fixture.
  **Готово:** отдельный маленький прогон на выбранном каталоге работает без сети;
  несовпадение классов, среды или checksum отклоняется; источник совпадает во всех
  артефактах. **Зависимости:** ML01.

- [x] **ML03 · P0 · Серии экспериментов на нескольких seed.** Добавить команду серии,
  заранее заданный список seed, сохранение отдельных run-ID и общий отчёт. Для
  каждого seed сравнивать модели и условия на согласованных base IDs. Показывать
  среднее, стандартное отклонение и число успешных прогонов; не смешивать
  несовместимые протоколы. Сохранять ожидаемый список seed и config/source hashes
  каждого прогона. В сравнительные агрегаты включать только seed с полным набором
  моделей и условий; неполные и failed показывать отдельно, без подстановки нулей.
  Для стандартного отклонения использовать `ddof=1`, при числе прогонов меньше двух
  возвращать `null`. Измерение скорости повторять после прогрева и сохранять
  число повторов, медиану и p95. **Готово:** небольшой benchmark выполнен минимум
  на пяти фиксированных seed; агрегаты пересчитываются из исходных результатов;
  failed run явно учтён, test не используется для выбора порогов. Число seed —
  инженерный минимум этого этапа, а не доказательство статистической достаточности.
  **Зависимости:** ML01; ML02 нужен для серии на новом справочнике.

- [x] **ML04 · P1 · Более реалистичный генератор.** По отдельным подзадачам добавить
  Voigt-профиль, Poisson/read noise, response и насыщение детектора. Параметры и
  единицы каждого механизма описывать в manifest; сохранить текущий Gaussian-режим.
  **Готово:** тесты проверяют нормировку профиля с учётом конечного окна, предельные
  режимы, воспроизводимость и свойства шума; влияние каждого механизма измерено
  отдельным controlled sweep. **Зависимости:** ML01, ML03.

- [x] **ML05 · P1 · Исследование калибровки оценок.** Проверить калибровку Logistic
  OVR и Random Forest на выделенных данных внутри development-части; отделить
  обучение калибратора от выбора порогов и финального test. Добавить reliability
  plots и метрики калибровки, версионировать калибратор вместе с моделью.

  `calibrated` и `score_kind` описывают реально применённый метод и область проверки.

- [x] **ML06 · P2 · Стадии ионизации и системы длин волн.** Спроектировать представление

  раздельные шаблоны ионов покрыты тестами; старые несовместимые артефакты не
  загружаются молча. **Зависимости:** ML02, согласование контракта BE01.

- [x] **ML07 · P2 · Опциональная 1D CNN.** Подключить новую модель через существующий
  интерфейс estimator, выделить зависимости обучения в extra и сохранять checkpoint,
  seed, class order и preprocessing. Версионировать формат checkpoint и его
  безопасную загрузку из доверенного каталога с проверкой целостности; расширить
  registry и проверки совместимости за пределы нынешнего joblib-контракта.
  Использовать multi-label постановку.
  **Готово:** round-trip модели проходит; сравнение с тремя baseline выполнено по
  ML03 с теми же split и протоколом настройки; минимальный runtime работает без

  `/predict`, без него сервис стартует и объясняет недоступность CNN. CNN
  принимается по измеренным результатам, преимущество заранее не предполагается.
  **Зависимости:** ML03, BE01.

- [x] **ML08 · P2 · Валидация на реальных измерениях.**
  Завершён внешний тест ChemCam: подтверждены лицензия и vacuum-шкала; 64 физических

  опубликованы; H/He неизвестны, F1/precision не определены без отрицательных меток.

  использования, прибор, эталонный состав, единицы, калибровку и идентификаторы
  образца/сессии. Зафиксировать внешний test до настройки transfer synthetic→real.
  **Готово:** опубликован протокол и отчёт с происхождением данных, разделением по
  физическому образцу/сессии, метриками и ограничениями; отсутствие данных явно
  блокирует задачу. **Зависимости:** ML02, ML03 и доступ к измерениям; BE04 — для
  импорта через приложение.

- [x] **ML09 · P2 · Неизвестные элементы и отказ от ответа.** Сначала определить
  open-set протокол: известные классы, удержанные неизвестные элементы, смеси и
  неподходящие входы. Затем исследовать abstention отдельно от порогов обнаружения.
  **Готово:** отдельно измерены ложные принятия неизвестного и отказы на известном;
  пороги настроены без test; обычный пустой `detected_elements` не называется
  обнаружением неизвестного вещества. **Зависимости:** ML02, ML03; заявления о
  реальных измерениях допускаются только после ML08.

## Исходная последовательность реализации

| Этап | Основные задачи | Условие завершения |
| --- | --- | --- |
| 1. Надёжная основа | ML01, BE01, FE01, FE06, FE08 | Строгие конфиги, явный контракт, автоматический сценарий через три части |
| 2. Источники и повторяемость | ML02, ML03; затем BE02, BE03 и FE02, FE03 | Трассируемый справочник и серия минимум из пяти seed доступны в отчёте и UI |
| 3. Рабочее место исследователя | BE04 → BE05 → FE04; параллельно FE05, FE09 | Сохранённые исследования находятся, повторяются и экспортируются |
| 4. Расширение исследований | ML04, ML05; затем выбранные ML06–ML09 | Каждое расширение имеет собственный протокол и воспроизводимое сравнение |
| 5. Совместное использование при необходимости | BE06 → FE07; BE07 перед сетевым запуском | Задания и доступ к данным проверены в выбранной среде |

ML03 можно начать на существующем fixture параллельно с ML02. Frontend может
разрабатываться по согласованным контрактным fixtures, но готовность подтверждается
на настоящем API. Изменения общих схем согласованы между направлениями; итог проверен
сквозными сценариями настоящего API.

## Критерии готовности изменений

Задача закрывается после реализации, целевой проверки её критерия и обновления
документации. Для изменений кода сохраняется текущий набор команд CI:

```bash
make api-types
git diff --exit-code -- frontend/src/api/schema.d.ts
make lint test build demo analytics
make browser-install
make e2e
```

Проверка diff сгенерированных типов выполняется после включения обновлённой схемы
в коммит: повторная генерация не должна менять её. E2E включён в CI; серии воспроизводятся через `make series CONFIG=...`.
Большие исследования запускаются отдельно от smoke и обычного CI.

Во всех направлениях сохраняются ограничения: `component_weights` не являются
концентрациями; некалиброванный score не называется вероятностью; синтетическое
качество не переносится на реальные измерения без проверки; true labels не
поступают в predictor; test не используется для настройки. Большие данные, модели
и локальные результаты остаются вне Git.
