# TODO план развития SpectraLab

План охватывает три направления проекта: ML и исследования (`ml/`), API и хранение
(`backend/`), интерфейс исследователя (`frontend/`). Это предлагаемые следующие
этапы после рабочего MVP. Все пункты ниже ещё предстоит выполнить; приоритет P0
означает ближайшую итерацию, а не наличие критической ошибки.

Основа плана — состояние `bb2cfc7`: генерация и загрузка спектра, общий preprocessing,
NNLS, Logistic OVR, Random Forest, сохранение экспериментов и три страницы интерфейса
уже реализованы. Повторно создавать эти возможности не нужно.

Приоритеты: **P0** — воспроизводимость и согласованность трёх частей;
**P1** — удобство исследований и расширение модели;
**P2** — отдельные исследования или функции, зависящие от реальных данных и условий
развёртывания. Сроки следует оценивать после выбора задач и исполнителей.

## Backend и хранение

[схемы API](../backend/app/schemas/api.py),
[хранилище](../backend/app/services/storage.py), [API](api.md).
Сервис уже валидирует вход, ограничивает загрузки, проверяет доверенные модели и
работает с локальными JSON-файлами в одном процессе.

| 3. Рабочее место исследователя | BE04 → BE05 → FE04; параллельно FE05, FE09 | Сохранённые исследования находятся, повторяются и экспортируются |
| 4. Расширение исследований | ML04, ML05; затем выбранные ML06–ML09 | Каждое расширение имеет собственный протокол и воспроизводимое сравнение |
| 5. Совместное использование при необходимости | BE06 → FE07; BE07 перед сетевым запуском | Задания и доступ к данным проверены в выбранной среде |

ML03 можно начать на существующем fixture параллельно с ML02. Frontend может
разрабатываться по согласованным контрактным fixtures, но готовность подтверждается
на настоящем API. Для одновременной реализации разными исполнителями нужны отдельные
ветки/worktree; изменения общих схем сначала согласуются между направлениями.

## Критерии готовности изменений

Задача закрывается после реализации, целевой проверки её критерия и обновления
документации. Для изменений кода сохраняется текущий набор команд CI:

```bash
make api-types
git diff --exit-code -- frontend/src/api/schema.d.ts
make lint test build demo analytics
```

Проверка diff сгенерированных типов выполняется после включения обновлённой схемы
в коммит: повторная генерация не должна менять её. Новые E2E и команды серий будут
добавлены соответствующими задачами; сейчас они не заявляются существующими.
Большие исследования запускаются отдельно от smoke и обычного CI.

Во всех направлениях сохраняются ограничения: `component_weights` не являются
концентрациями; некалиброванный score не называется вероятностью; синтетическое
качество не переносится на реальные измерения без проверки; true labels не
поступают в predictor; test не используется для настройки. Большие данные, модели
и локальные результаты остаются вне Git.
