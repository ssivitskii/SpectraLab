# Улучшение приборной модели: development v2

Итерация 2026-10-13 добавила четыре новых низкосодержащих Mg-материала,
проверку различий между кампаниями и модель с UV/видимыми линиями.
Вложенная групповая перекрёстная проверка показывает улучшение для Mg и Fe.
**Новый независимый тест с Fe/Mg blank-контролями не выполнен:** подходящий
набор с подтверждёнными исходными спектрами, правами, шкалой и химическими
границами blank не найден. Новых низкосодержащих Fe-материалов также не добавлено.

Исходный [test v1](instrument_adaptation.md) уже раскрыт и теперь является
частью development. Его нельзя повторно объявлять независимым тестом. Реализация,
артефакты и результаты исходного v1 сохранены без изменения.

## Различия между кампаниями

Диагностика использовала только ранее раскрытые 198 спектров / 195 материалов.
По 32 фиксированным признакам обучался классификатор принадлежности к кампании,
а не состава. Scaler и классификатор обучались отдельно внутри групповых folds.
Физические материалы, семейства и связанные сессии не пересекают границы folds.

| Признаки / подгруппа | Grouped OOF ROC-AUC кампании |
| --- | ---: |
| Спектральные признаки, все материалы | 0.923 |
| Только пороговые химические метки, все материалы | 0.705 |
| Спектральные признаки, Mg positive | 0.889 |
| Спектральные признаки, Mg negative | 0.850 |
| Спектральные признаки, Fe positive | 0.933 |
| Fe negative | Не оценено: в фиксированном разбиении есть fold с одной кампанией |

Кампании различимы даже внутри некоторых групп состава. Это **не доказывает
дрейф прибора**: нет общих независимых контрольных образцов, а пороговые метки
не выравнивают всю матрицу и концентрации. Seed и число folds не подбирались
для получения удобной оценки Fe negative. Полные распределения, поддержка,
разбиения и ограничения: [сводка диагностики](campaign_shift_v2_summary.json),
локальный run `reports/campaign_shift_v2/diagnostic-20261013T163803-4b10cde1/`.

## Изменение модели и протокол сравнения

V1 использовала только видимую часть измерений. V2 добавляет доступный UV-канал
241–340 nm и признаки линий Na/Mg/Ca/Fe I–II. Полосы обработки — 241–340,
383–468 и 474–900 nm, сетка 0.1 nm, среднее shots 6…N. Разрывы между
детекторами не интерполируются как наблюдённый сигнал.

Линии выбраны по закреплённым выгрузкам NIST, без подбора по измеренным ответам.
Вариант UV сохраняет все линии видимого варианта и добавляет UV-линии.
Например, vacuum Mg I — 285.2965 nm, Mg II — 279.6352 и 280.353 nm.
Близкие air-значения нельзя подставлять в vacuum-сетку. Восемь выгрузок NIST,
параметры `show_av=3`, исходные заголовки и SHA-256 находятся в
[reference cache](../data/reference/nist_uv_visible_v2/).

Для каждой линии извлекаются превышение над локальным фоном, нормированное
на положительный сигнал своей полосы, и отношение к локальному фону.
Нормировки устойчивы к общему положительному множителю отклика внутри полосы;
это эмпирическая поправка, не восстановленная физическая response function.
Каждый элемент использует признаки своих линий. Взвешенная логистическая
регрессия уравнивает классы и суммарный вклад повторов физического материала.
Unknown-метки исключены из fit соответствующего элемента и scaler.

Development содержит **202 спектра / 199 физических материалов**: прежние
127 development, 71 раскрытый test и 4 новых спектра. Правила меток сохранены:
для Na₂O/MgO/CaO/FeOT `0 < x <= 0.1 wt%` — negative, `x >= 1` — positive;
ноль, пропуски и промежуточные значения — unknown. Это распознавание превышения
уровня, не концентрационная модель и не доказательство отсутствия элемента.

Пять внешних grouped folds оценивают качество; внутри каждого — три grouped
folds для выбора C из `[0.01, 0.1, 1]` и порогов. Порог максимизирует recall
при внутренней точечной FPR ≤5%; это ограничение выбора, не гарантия внешней
FPR. Внешний fold не используется при выборе C, scaler или порогов. Связи
physical/family/session/checksum объединяются транзитивно. План, признаки,
источники и разбиения сохранены до fit. UV-вариант заранее обозначен основным.

## Измеренное качество на development

Числа ниже — объединённые внешние OOF-предсказания вложенной проверки.
Повторные спектры имеют суммарный вес одного физического материала.
V1 здесь заново обучена на том же development и тех же разбиениях; её прежний
однократный test не является сопоставимой строкой этой таблицы.

| Модель | Na recall / FPR | Mg recall / FPR | Ca recall / FPR | Fe recall / FPR | Macro balanced accuracy |
| --- | ---: | ---: | ---: | ---: | ---: |
| V1, бины | 86.7% / 1.6% | 81.8% / 0% | 88.2% / 7.8% | 75.5% / 8.0% | 89.35% |
| V2, видимые линии | 74.0% / 4.7% | 87.9% / 2.6% | 91.4% / 2.0% | 83.0% / 8.0% | 89.88% |
| V2, UV + видимые линии | 84.0% / 0% | 96.0% / 0% | 92.5% / 3.9% | 93.6% / 4.0% | 94.77% |

Поддержка positive/negative по материалам: Na 75/64, Mg 99/39, Ca 93/51,
Fe 141/25; остальные метки неизвестны. Для V2 UV: Mg TP=95, FN=4, FP=0,
TN=39; Fe TP=132, FN=9, FP=1, TN=24. Улучшение не универсально:
recall Na относительно переобученной V1 снизился с 86.7% до 84.0%.

Нулевая наблюдаемая FPR не означает отсутствия риска. Особенно мало Fe negative.
Групповые интервалы в JSON условны на уже полученных OOF-моделях; они не включают
полную изменчивость переобучения. Результаты не доказывают перенос на новый прибор
или независимую кампанию с blank-контролями.

Фактический run: `reports/adaptation_v2/development-20261013T164342-b37a6ab8/`.
В нём сохранены план, OOF scores/detections, выбор C и порогов каждого fold,
numeric JSON profile и хеши реализации. [Машиночитаемая сводка](instrument_v2_summary.json)
явно содержит `scope: nested_grouped_development_cv_not_independent_test` и
`independent_final_test: false`. Унаследованное имя поля `test_measurement_ids`
в метриках здесь обозначает OOF-строки development, не новый final test.
Профиль для применения fit на всём development, C=1; его обучающие результаты
не выдаются за OOF-метрики.

## Независимые blank-контроли: открытый пункт

[Реестр внешних кандидатов](../data/reference/blank_candidates_v2.json) и
[ChemCam audit](../data/reference/chemcam_v2_candidate_audit.json) фиксируют
12 проверенных внешних источников и причины отказа. Например,
[набор фильтров водорослей](https://doi.org/10.5281/zenodo.15650002) и
[SuperLIBS](https://doi.org/10.5281/zenodo.10287455) имеют подтверждённую CC BY 4.0,
но документированная шкала и подходящие Fe/Mg blank-границы не подтверждены.
В первом случае статья описывает blank края фильтров с возможными следовыми
примесями; его нельзя объявить нулём Fe/Mg без химического основания.
В ChemCam Mn blank — контроль Mn, но не автоматически Fe/Mg. Ti target —
сплав с Al/V, а не подтверждённый высокочистый Ti; для graphite загрязнения
описаны, но нужные границы не заданы.

Программная проверка допуска требует новые исходные численные спектры,
подтверждённую лицензию, `air`/`vacuum` шкалу с явной конверсией при необходимости,
независимые material/family/session/raw/assay IDs и отбор до предсказаний.
Для method/matrix blank нужны документированные верхние границы FeOT и MgO
не выше 0.1 wt% и сведения о подготовке. Общий URL или SHA таблицы состава
не создаёт ложное пересечение материалов; учитывается identity конкретного анализа.
Dark/no-laser, ноль в таблице и номинальная формула минерала контролем не считаются.
Guard проверяет структуру метаданных, их связи и контрольные суммы; истинность
подтверждений и хронологию отбора нужно проверять по первичным свидетельствам.
Само поле `certified: true` не создаёт химического сертификата.

[Допуск final v2](../data/reference/chemcam_v2_final_admission.json) имеет
`status: blocked`; итоговые метрики отсутствуют. Это означает недостаток
доказательств для допуска, а не измеренное нулевое качество. Для завершения
нужна новая независимая кампания, включающая такие blank и образцы с известными
низкими/высокими Fe/Mg. После допуска требуется заранее закрепить протокол,
неизменяемый профиль и выполнить однократную финальную оценку.

## Воспроизведение и применение

```bash
# Проверить/получить четыре закреплённых новых development-спектра
make instrument-v2-data
# Проверить/получить закреплённые vacuum NIST exports
make instrument-v2-reference
# Только диагностика раскрытых v1-кампаний
make campaign-shift-v2
# Новый run вложенного development CV; это не независимый final test
make instrument-v2-development

# Применить уже сохранённый numeric profile; output должен быть новым
.venv/bin/python scripts/predict_line_v2.py \
  --artifact reports/adaptation_v2/development-20261013T164342-b37a6ab8/profile.json \
  --input /path/to/measurement_ccs.csv \
  --instrument-id chemcam-lanl-testbed --output reports/v2-prediction.json
```

CLI проверяет прибор, identity, размеры и конечность чисел, фиксированный план
полос/линий и покрытие исходного CCS. Он сохраняет provenance, score, пороги,
`calibrated: false`, `qualification: development_only_no_independent_blank_validation`
и `final_test_status: not_performed`. Score — некалиброванная оценка модели,
не вероятность. H/He остаются unknown. Профиль остаётся исследовательским.
